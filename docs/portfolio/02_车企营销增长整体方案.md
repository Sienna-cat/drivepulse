# 项目 A｜汽车营销增长产品整体方案

性质：结合真实经历形成的个人方案。目标用户是一线线索运营与销售顾问；总部/门店负责人关注配置、承接和结果。现有原型各自验证局部机制，整体架构尚未接通生产系统。

## 1. 业务问题与价值假设

需要解决的任务是：把已获客线索持续推进为有依据、有人负责、有明确下一步的跟进任务。已有经历支持标签不清、信息断层与承接不及时这类问题；各断点的当前规模和成本需通过任务回放验证。

价值假设：减少销售重复确认和无效承接，在不增加打扰与漏判的前提下改善单位有效承接成本。没有试点前不承诺试驾或成交提升。

## 2. 业务链路与角色

渠道留资 → 客户去重/触达资格 → 客群优先级 → 外呼理解与信息补全 → 企微/人工承接 → 顾问跟进/试驾确认 → 结果回流。车主关怀作为成交后的后续延伸。

| 角色 | 核心任务 | 系统应提供什么 |
| --- | --- | --- |
| 线索运营 | 配置目标人群、检查触达资格、分派任务 | 规则版本、名单差异、容量与失败原因 |
| 销售顾问 | 理解需求、接手沟通、确认下一步 | 原始表达、摘要、缺失项、联系人和截止时间 |
| 业务负责人 | 定义有效线索、判断投入与损失 | 去重漏斗、成本、承接时效、退回原因 |
| 质检人员 | 复核标签和动作、处理争议 | 对话证据、版本、独立标注、复测记录 |

## 3. 产品结构与取舍

业务工作区包括线索池、客群策略、外呼任务、承接队列、客户档案与效果复盘。共享设计对象为客户标识、对话证据、标签版本、任务状态和事件时间；这些是目标架构，不是现有四个 Demo 已共享的数据库。

优先建设：触达资格、意向与动作分开、交接摘要、任务领取与回写。理由是这些能力直接决定一次线索任务能否完成。暂缓多渠道自动预算优化、全量客户数据平台和自动成交归因，避免在有效线索定义尚未稳定时扩大系统范围。

## 4. 指标树

业务主指标建议：固定观察窗口内，每千条符合资格的去重入池线索，产生多少条销售确认有效且完成首次联系的线索。

- 入池与触达：去重入池数、资格通过数、已尝试触达数、去重接通数。
- 判断与承接：意向可判定数、高意向漏判、人工受理数、销售有效数、首次联系完成数。
- 后续转化：已确认试驾、实际到店/试驾、后续订单。须按成熟窗口观察，不把预约创建视为到店。
- 成本与质量：单位有效承接总成本、人工复核分钟数、拒联后触达、重复任务、超时未接手。

成本纳入线索获取、外呼/通道、模型与工具、人工复核和承接。不同分母不在同一个百分比图中混算。

## 5. 建设与验证顺序

阶段 1：任务回放与基线。看一条线索怎么进入、由谁接手、失败在哪里；输出实际状态字典和指标 SQL/口径。

阶段 2：单场景 MVP。选一个地区/渠道，跑通“资格 → 识别 → 摘要 → 人工确认 → 承接 → 回写”；先影子运行，再小范围使用。

阶段 3：质量与容量验收。统一高意向定义，检查异常、接手时效、人工负载和总成本；达到业务共同制定的门槛再扩大。

阶段 4：拓展客群策略与车主运营，加入新批次评测。地址核验仅在有履约任务时接入。

## 6. 作品集证据与个人贡献

DriveFollow 证明顾问确认、引用与预约状态；DrivePulse 证明筛选、资格、审批、反馈。个人作品中负责场景、规则、交互和验证设计，借助 Codex 实现。没有以这些原型证明实际获客或留存收益。
