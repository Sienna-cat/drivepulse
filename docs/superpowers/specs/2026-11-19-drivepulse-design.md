# DrivePulse 车主运营工作台：设计规范

设计版本：2026-11-19；交互应用与项目说明已交付。

## 目标与边界

面向车主运营人员，演示“识别活跃下降且有服务需求的车主—检查触达限制—审核方案—创建模拟任务—记录结果—复盘”的完整任务。桌面工作区以信息架构、任务交办、人工干预、工具执行与验收组织。

所有车主、规则与业务记录均为虚构；不代表蔚来内部系统或真实业务结论。当前使用确定性规则与文案模板，不接入大模型，不对外发送消息。不会将离线演示数据包装成业务提升。

## 交付与技术

- 独立目录 `drivepulse`；使用 HTML、CSS、浏览器 ES Modules，无外部网络依赖。
- Node.js 22+ 原生静态服务与原生 test runner；无需安装第三方依赖。
- 状态保存在当前浏览器 localStorage；不提供多人同步或账号权限。
- 桌面宽屏优先，同时适配 390px 手机视口。
- 固定演示业务日期为 2026-11-19，界面明确标记。

## 业务口径

首版固定比较两个连续 30 天窗口。活跃下降比例 = (前 30 天访问次数 − 近 30 天访问次数) / 前 30 天访问次数。前期访问次数为零不进入下降分群。运营目标自由文本用于记录，筛选由城市、下降阈值和“存在服务需求”结构化条件决定。

候选人群检查：退订、未解决投诉、联系信息不完整、7 天内已联系。分别排除或转人工提示。规则来源和车主记录引用可查看。事实、建议、已执行动作使用不同标签。

任务状态：running → awaiting_approval → approved → completed；工具失败进入 blocked，重试保留已有步骤；规则过期需要更新演示规则后恢复。等待审批时可以修改文案和取消部分车主。审批前再次检查规则、人群资格与非空文案；同一运行重复批准不会重复创建任务。

结果状态：pending、contacted、responded、declined、manual。拒绝后标记退订，影响后续运行；响应后给出人工确认服务时间的下一步，不能直接冒充预约成功。记录已触达不等同于客户已响应。拒绝和响应是互斥的当前结果。

## 页面与信息架构

1. 工作台：业务数据概览、目标输入、结构化筛选、近期任务和人群构成。可以直接发起正常运行，也可选择工具失败或规则过期演示。
2. 任务中心/工作区：任务列表与详情；时间线展示实际执行步骤、来源和结构化工具结果；方案有可修改文案、可选择车主、排除依据与人工审批入口。
3. 车主资料：搜索和城市过滤，展示虚构车主事实、服务需求、触达限制；不生成未经证实的个人画像。
4. 结果复盘：从当前浏览器实际任务与反馈计算统计；无数据时显示空态；展示排除原因、工具失败和人工修改记录。
5. 作品集说明：业务问题、产品设计、架构、关键取舍、工具契约和场景检查。

视觉：暖白背景、浅灰导航、墨绿与青绿强调；大字标题、细边框、克制卡片；避免把产品做成只有聊天的页面。所有主要控件可键盘操作，弹窗可关闭，状态反馈使用可访问标签。

## 核心接口

`createState()` 创建演示数据；`queryOwnerSegment(state, filters)` 返回候选；`screenOwners(owners)` 返回合格与排除项；`beginRun(state, input)` 创建运行；`advanceRun(state, id)` 执行下一个工具；`retryRun(state, id)` 恢复失败步骤；`approveRun(state, id, { selectedIds, message })` 创建去重任务；`recordOutcome(state, operationId, outcome)` 保存反馈；`getMetrics(state)` 计算真实本地统计。

工具日志只记录执行动作与返回值，不展示虚构模型思考过程。`queryOwnerSegment`、`getOwnerFacts`、`retrieveOperationPolicy`、`createOperationTask`、`recordOperationOutcome` 为本地实现。

## 验收

- 初次打开可直接启动示例任务，正常流程能到达审批并创建待执行任务。
- 排除退订、投诉、信息缺失和频繁触达；来源可查看。
- 审批前不得创建运营任务；重复批准不重复写入。
- 文案修改与人群选择进入保存的结果；刷新后恢复。
- 查询失败可重试；过期规则阻断并可用演示更新恢复。
- 反馈改变复盘指标；拒绝状态影响下一次候选筛选。
- 测试覆盖业务边界，浏览器验收主流程、异常恢复、持久化、导航与窄屏。
- README 提供启动、测试、演示步骤和限制说明。

## 后续验证

本次交付不能证明运营提效或留存提升。下一阶段应访谈实际运营人员，定义真实规则，使用同难度案例对比人工与辅助流程；接入模型时保留确定性资格校验、幂等写入和人工审批。
