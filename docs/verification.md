# DrivePulse 验证记录

日期：2026-11-19（Asia/Shanghai）。验证对象是本地规则工作流原型，不是运营效果或大模型质量评测。

## 自动化业务测试

命令：`node --test tests/engine.test.js`。

结果：10 个测试通过，0 失败。编写测试后首先在未实现的领域接口上观察到 10 个失败，再实现业务行为并运行至通过。

覆盖：

1. 分群排除零基线、无服务需求、城市不符、下降不足。
2. 资格筛选覆盖退订、投诉、联系方式缺失、7 天触达边界。
3. 审批之前不创建运营任务。
4. 修改文案与选择人群正确写入；同一运行重复批准不重复创建。
5. 空文案、空选择、无效 ID、审批时资格变化会被拒绝。
6. 查询失败可恢复，失败与成功记录均保留。
7. 过期规则阻断；显式更新演示规则后从原步骤继续。
8. 反馈驱动指标；拒绝联系更新退订并影响后续筛选。
9. 非法结果值被拒绝；相同结果重复提交不重复记录。
10. 无合格人群时可查看方案，但无法批准。

`src/app.js`、`src/engine.js`、`src/portfolio.js`、`server.mjs` 均通过 Node 语法检查。

## 检查中发现并修复

- 审核草稿仅在 DOM 中：改为每次编辑保存草稿，刷新后恢复。
- 刷新后运行停滞：启动时从保存的步骤恢复正在运行的任务。
- 已触达后无法再反馈：保留结果更新入口与历史。
- 手机端下拉框撑开表单：缩小网格轨道最小宽度，并限制表单控件宽度。
- 独立代码检查发现后台 tick 重绘工作台会覆盖新交办草稿：后台执行现在只更新当前任务详情，交办表单也保存草稿。已在浏览器复现并回归。
- 独立检查发现响应任务数被写成人数：改成“条任务已响应”，与指标分母一致。
